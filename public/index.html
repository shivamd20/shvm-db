The Vision

DynamoDB scales to absurd throughput not because of magic, but because of brutal operational discipline. shvm-db forces you to understand these physics by rebuilding them yourself.

Core Principles

  • Exact Parity: PutItem, GetItem, Query—same semantics, same constraints.
  • Single Writer: One partition key maps to exactly one Durable Object.
  • Zero Layers: No hidden caches. SQLite is the only source of truth.
  • Pay-per-Request: Scale to zero when idle, scale to infinity when hot.

Architecture & Throughput

We achieve massive throughput by splitting the world into Micro-Partitions.

Client Any DynamoDB SDK
Worker Router Hash(PK) → ID
Durable Object Single Threaded/Partition
SQLite On-Disk Storage

Micro-Partitions

Each partition is an isolated V8 isolate. 1,000 partitions = 1,000 parallel CPUs.

Latency Targets

Read: <5ms (Hot), Write: <10ms. Achieving this via in-memory SQLite page caching.

Throughput Roadmap

Future: In-memory Bloom Filters to skip disk I/O for 404s, and HashMap indexes for O(1) reads.

Zero Magic

Understanding distributed systems by removing the abstraction layers. One partition = One Durable Object.

DynamoDB Compatible

Drop-in replacement. If it runs on DynamoDB, it runs on shvm-db (eventually).

Serverless Native

Built on the edge. No servers to manage, no capacity to provision.
